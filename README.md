## 1. Назначение проекта

**Цель:** познакомить студентов с полным циклом разработки IoT-системы.

**Что демонстрирует проект:**

- чтение физических величин микроконтроллером (датчик DHT22);
- передачу данных по сети (HTTP, JSON);
- серверную часть (приём, хранение, выдача данных);
- веб-интерфейс для визуализации и мониторинга;
- диагностику состояния устройств (онлайн/офлайн, ошибки датчиков).

**Практическая ценность:** готовый шаблон для мониторинга серверной, теплицы, склада, учебной лаборатории.

**Дисциплины:** «Интернет вещей», «Микроконтроллеры», «Веб-программирование», «Базы данных», «Сети передачи данных».

## 2. Архитектура

```
┌─────────────┐    Wi-Fi / Ethernet     ┌──────────────┐
│  Устройство │ ──── HTTP POST JSON ──> │   Сервер     │
│ ESP32/Mega  │                         │  Flask +     │
│  + DHT22    │ <─── HTTP 201 OK ─────  │  SQLite      │
└─────────────┘                         └──────┬───────┘
                                               │
                                    HTTP GET   │
                                               ▼
                                        ┌──────────────┐
                                        │  Браузер     │
                                        │  веб-дашборд │
                                        └──────────────┘
```

**Поток данных:**

1. Датчик DHT22 измеряет температуру и влажность.
2. Микроконтроллер раз в 10 секунд отправляет POST на `/api/data`.
3. Сервер сохраняет запись в SQLite.
4. Веб-страница каждые 5 секунд запрашивает `/api/data` и `/api/devices` и обновляет таблицу и статусы.

## 4. Требования

### Оборудование (на одного студента или бригаду)

**Вариант A — ESP32 (Wi-Fi):**

- ESP32 DevKit (любая плата)
- Датчик DHT22 + резистор 10 кОм
- USB-кабель, провода, макетная плата

**Вариант B — Arduino Mega (Ethernet):**

- Arduino Mega 2560
- Модуль W5500 (Ethernet)
- Датчик DHT22 + резистор 10 кОм
- Ethernet-кабель, провода, макетная плата

### Программное обеспечение

- Python 3.9+
- Arduino IDE 2.x
- Браузер (Chrome, Firefox, Edge)

### Сеть

- ПК с сервером и плата — **в одной локальной сети** (один роутер)
- Wi-Fi **2.4 ГГц** (ESP32 не поддерживает 5 ГГц)
- Свободный порт **5000 TCP** на ПК

## 5. Быстрый старт

### 5.1. Запуск сервера

```bash
# Из папки проекта
pip install -r requirements.txt
python app.py
```

В консоли появится:

```
 * Running on http://0.0.0.0:5000
```

Откройте **http://localhost:5000** — увидите пустой дашборд с надписью «Нет подключённых устройств». Это нормально.

### 5.2. Узнайте IP компьютера

- **Windows:** `ipconfig` → строка «IPv4-адрес»
- **Linux/macOS:** `ip a` или `ifconfig`

Пример: `192.168.1.100`. Запишите его — понадобится в скетче.

### 5.3. Разрешите порт 5000 в брандмауэре

**Windows (PowerShell от администратора):**

```powershell
New-NetFirewallRule -DisplayName "Flask IoT 5000" -Direction Inbound -LocalPort 5000 -Protocol TCP -Action Allow
```

**Linux (ufw):**

```bash
sudo ufw allow 5000/tcp
```

> ⚠️ ПК с сервером должен быть включён всё время работы. Отключите сон в настройках питания.

## 6. Подключение оборудования

### 6.1. DHT22 к ESP32

| DHT22 | ESP32 |
|-------|-------|
| VCC (1) | 3.3V |
| DATA (2) | GPIO 4 (через резистор 10 кОм к VCC) |
| NC (3) | — |
| GND (4) | GND |

### 6.2. DHT22 + W5500 к Arduino Mega

**DHT22:**

| DHT22 | Mega |
|-------|------|
| VCC | 5V |
| DATA | D4 (через резистор 10 кОм к VCC) |
| GND | GND |

**W5500 (SPI):**

| W5500 | Mega |
|-------|------|
| VCC | 5V |
| GND | GND |
| CS | D10 |
| MOSI | D51 |
| MISO | D50 |
| SCK | D52 |

## 7. Настройка Arduino IDE

1. Установите **Arduino IDE 2.x**.

2. **Для ESP32:** Файл → Настройки → «Дополнительные ссылки для менеджера плат» → добавьте:

   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

   Затем Инструменты → Плата → Менеджер плат → установите **esp32**.

3. **Для Mega:** ничего устанавливать не нужно, плата есть в IDE по умолчанию.

4. Установите библиотеки: Инструменты → Управление библиотеками:

   - `DHT sensor library` (Adafruit)
   - `Adafruit Unified Sensor`
   - `ArduinoJson` (версия **6.x**)
   - `Ethernet` (только для Mega — обычно уже встроена)

## 8. Прошивка платы

### 8.1. ESP32

Откройте `sketches/iot_sensor.ino` и измените:

```cpp
const char* WIFI_SSID     = "ВАШ_WIFI";        // 2.4 ГГц!
const char* WIFI_PASSWORD = "ВАШ_ПАРОЛЬ";
const char* SERVER_URL    = "http://192.168.1.100:5000/api/data";  // IP из шага 5.2
const char* DEVICE_ID     = "esp32-01";        // уникальное имя
```

Выберите плату **ESP32 Dev Module** и порт, нажмите **Загрузить**.

### 8.2. Arduino Mega

Откройте `sketches/mega_ethernet_iot.ino` и измените:

```cpp
IPAddress serverIP(192, 168, 1, 100);   // IP из шага 5.2
const char* DEVICE_ID = "mega-01";
```

Выберите плату **Arduino Mega or Mega 2560** и порт, нажмите **Загрузить**.

> 💡 **Каждой бригаде — свой `DEVICE_ID`:** `esp32-01`, `esp32-02`, `mega-01`. Тогда на одном сервере видно все устройства сразу.

## 10. Эксперименты

Выполните и опишите в отчёте:

1. **Офлайн-статус.** Отключите питание платы. Через ~1 минуту карточка должна стать красной (офлайн).
2. **Ошибка датчика.** Отсоедините DATA у DHT22. В таблице появятся строки с `sensor_timeout` на красном фоне.
3. **Обрыв Wi-Fi.** Выключите роутер. Плата должна писать в Serial «Wi-Fi потерян, переподключение...», после включения роутера — восстановить отправку.
4. **Неверный IP сервера.** Поменяйте `SERVER_URL` на заведомо неверный — в Serial увидите ошибку подключения.
5. **Несколько устройств.** Прошейте вторую плату с другим `DEVICE_ID` — обе появятся на дашборде одновременно.

## 11. Диагностика проблем

| Симптом | Причина | Решение |
|---------|---------|---------|
| `HTTP -1` (ESP32) / «Не удалось подключиться» (Mega) | Сервер не запущен, неверный IP, блокирует файрвол | Проверить `python app.py`, IP, правило файрвола |
| `T=nan H=nan` | Неверное подключение DHT22, нет резистора, не тот тип | Проверить провода, резистор 10 кОм, `DHTTYPE` |
| ESP32 не подключается к Wi-Fi | Сеть 5 ГГц | Использовать сеть **2.4 ГГц** |
| Mega: DHCP не сработал | Нет DHCP-сервера в сети | Задать статический IP: `Ethernet.begin(mac, ip)` |
| Данные идут, но страница пустая | Кэш браузера / не та вкладка | Обновить страницу, проверить `/api/data` |
| ArduinoJson ошибки компиляции | Установлена версия 7.x | Установить 6.x |
| ПК ушёл в сон → данные пропали | Энергосбережение | Отключить сон в настройках питания |
| `OSError: [Errno 98] Address already in use` | Порт 5000 занят | Закрыть другой Flask или сменить порт в `app.py` |

## 15. API сервера

| Метод | Путь | Назначение |
|-------|------|-----------|
| `GET` | `/` | Веб-дашборд |
| `POST` | `/api/data` | Приём данных от устройства |
| `GET` | `/api/data?limit=N` | Последние N записей (по умолчанию 50, максимум 500) |
| `GET` | `/api/devices` | Статус устройств (online/offline, счётчик) |
| `GET` | `/health` | Health-check (200 — ок, 503 — БД недоступна) |

### Пример POST

```bash
curl -X POST http://localhost:5000/api/data \
  -H "Content-Type: application/json" \
  -d '{"device_id":"esp32-01","temperature":22.5,"humidity":45.1}'
```

Ответ: `201 CREATED` с телом `{"status":"ok"}`.

### Пример с ошибкой датчика

```bash
curl -X POST http://localhost:5000/api/data \
  -H "Content-Type: application/json" \
  -d '{"device_id":"esp32-02","error":"sensor_timeout"}'
```

### Формат ответа `GET /api/devices`

```json
[
  {
    "device_id": "esp32-01",
    "last_seen": "2025-01-15T10:23:45.123456",
    "online": true,
    "readings": 120,
    "seconds_ago": 5
  }
]
```
